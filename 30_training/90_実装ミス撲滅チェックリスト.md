# 実装ミス撲滅チェックリスト

あなたのリポジトリで実際に起きたミスに基づく。**提出前に上から機械的に回す**(30秒で終わる)。

## 提出前チェック(毎回)

- [ ] **デバッグ出力を消したか**(abc448_b_miss.cpp: `cout << id_a << endl;` が残ったまま)
- [ ] **llにすべき所がintのままでないか**: 和・積・カウンタ。`10^5 × 10^5 = 10^10` は int に入らない
- [ ] **配列サイズと添字**: `N+1` 確保したか、0-indexed/1-indexed をどちらかに統一したか
- [ ] **境界**: `i < N` と `i <= N`、`while` の終了条件を最小ケース(N=1)で頭の中で1周
- [ ] **サンプル全部**通したか。特に**最後のサンプル**(コーナーケースが仕込まれがち)
- [ ] 出力形式: 改行・スペース・YES/Yes・小数の桁数

## 書き始める前の習慣(バグの半分はここで防げる)

1. **3行設計**: ①データ構造 ②ループ/遷移 ③答えの出し方 をコメントで書いてから実装
2. **if-else 5個ルール**: 場合分けが5個を超えたら手を止める(abc424_d_faild.cpp は6分岐の場当たり貪欲で崩壊)。対称性・ループ化・そもそも別アルゴリズムを疑う
3. **変数名**: ループ変数の使い回し禁止(`j,k,n,m,l,o` が1関数に混在すると添字事故が起きる)。行/列は `i,j` か `h,w` に固定して統一
4. **コピペ改変禁止**: 似た処理を4回コピペするならループか関数にする

## テンプレート改善(推奨)

`src/template.cpp` が最小構成のまま。`make_abc.sh` 内のテンプレとも不一致なので、以下に統一を推奨:

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    // ① データ構造:
    // ② ループ/遷移:
    // ③ 答え:

    return 0;
}
```

- `'\n'` を使う(`endl` は毎回flushするので大量出力でTLE要因になる)
- インタラクティブ問題のときだけ `endl` に戻す

## テスト運用

`sample.in` 運用は既にあるので、1コマンド化しておくと本番で速い:

```bash
# 例: ./t.sh abc470 c
g++ -std=c++20 -O2 -Wall -Wextra -fsanitize=undefined -o main "src/$1/$1_$2.cpp" && ./main < sample.in
```

- `-Wall -Wextra` で未初期化・符号比較を警告させる
- `-fsanitize=undefined` は配列外アクセスとオーバーフローを実行時に検出してくれる(練習時は常時ON推奨)

## WAが出たときの手順(慌てない)

1. サンプルは通るのにWA → **コーナーケース**: N=1、全部同じ値、答えが0、最大値ギリギリ
2. 大きいケースだけWA → **オーバーフロー**を最初に疑う
3. それでも不明 → 愚直解(O(N^2)でよい)を書いてランダム入力で突き合わせ(ストレステスト)。5分で書けて確実に差分が見つかる
